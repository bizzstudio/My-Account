# מחיקת מספר תיקים (products) — דרישות מהבקאנד

הפרונט שולח **מחיקה מרובה** כשהמשתמש בוחר "בחר הכול" (או כמה שורות) ולוחץ "מחיקה".

## Endpoint שהפרונט קורא

- **Method:** `PATCH`
- **URL:** `{baseURL}/products/delete/many`
- **Body (JSON):** `{ "ids": ["id1", "id2", ...] }`

כל הערכים ב־`ids` הם **מחרוזות** (מזהי MongoDB ObjectId כמחרוזת).

## דוגמה לבקשה

```http
PATCH /products/delete/many
Content-Type: application/json
Authorization: Bearer <token>

{
  "ids": ["674a1b2c3d4e5f6789012345", "674a1b2c3d4e5f6789012346"]
}
```

## מה הבקאנד צריך לעשות

1. **אימות:** לוודא שהמשתמש מחובר (Bearer token) ומורשה למחוק תיקים (למשל לפי role / owner).
2. **מחיקה:** למחוק ממשית מכל ה־collections/טבלאות הרלוונטיות את כל המסמכים/רשומות שמזהה ה־`_id` שלהם מופיע ב־`ids`.
3. **תשובה:** להחזיר סטטוס 200 (או 204) בהצלחה. אם יש הודעת הצלחה, הפרונט יציג אותה.

## אם המחיקה "לא עובדת" — מה לבדוק בבקאנד

1. **האם ה-endpoint קיים?**  
   וודא שיש route ל־`PATCH .../products/delete/many` (או המקביל אצלכם).

2. **פורמט הגוף:**  
   הפרונט שולח **בדיוק** `{ ids: string[] }`. אם בבקאנד מצפים לשדה אחר (למשל `productIds`) או לפורמט אחר — צריך להתאים או את הבקאנד או את הפרונט.

3. **הרשאות:**  
   אם יש בדיקת הרשאה (למשל רק הבעלים או אדמין יכולים למחוק) — וודא שהמשתמש הנוכחי עובר את הבדיקה.

4. **מחיקה אמיתית:**  
   וודא שאחרי הקריאה ל־endpoint המסמכים באמת נמחקים מה-DB (או מסומנים כמחוקים אם יש soft delete).

5. **שגיאות:**  
   אם הבקאנד מחזיר 4xx/5xx, הפרונט יציג הודעת שגיאה. כדאי להחזיר `message` (או `message.he` / `message.en`) בתשובת השגיאה.

---

**סיכום:** הפרונט שולח `PATCH /products/delete/many` עם `{ ids: ["...", "..."] }`. הבקאנד חייב לממש את ה-endpoint הזה ולמחוק את כל התיקים שמזהיהם ב־`ids`.
